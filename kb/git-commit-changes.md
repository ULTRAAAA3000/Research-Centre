# Фиксация изменений

Коммит записывает снимок проекта в историю. Сначала выбранные изменения добавляются в **индекс** (`git add`), затем индекс фиксируется коммитом (`git commit`).

## Добавить и закоммитить

```bash
git add .                         # добавить в индекс все изменения текущей папки
git add <файл>                    # добавить один файл
git add -p                        # выбрать куски изменений по одному
git commit -m "описание"          # создать коммит с сообщением
git commit -am "описание"         # add для уже отслеживаемых файлов и commit
```

- `git add .` добавляет все изменённые и новые файлы текущей папки и вложенных. Перед ним выполните `git status`, чтобы не добавить лишнего: секретные файлы (`.env`, ключи), большие архивы, `node_modules`.
- `git add -p` позволяет разбить правки на логические коммиты: по каждому куску Git спрашивает `y` (добавить), `n` (пропустить).
- `-am` не добавляет новые файлы, только уже отслеживаемые.
- Хорошее сообщение коротко отвечает, что и зачем изменено: «fix: обработка пустого ответа API». Принято писать в повелительной форме и держать заголовок в пределах 50-70 символов.

## Отмена и исправление (до отправки на GitHub)

```bash
git restore --staged <файл>       # убрать файл из индекса (изменения останутся)
git restore <файл>                # отбросить правки файла в рабочей папке
git commit --amend                # изменить последний коммит
git commit --amend --no-edit      # добавить в последний коммит новые файлы
git reset --soft HEAD~1           # отменить последний коммит, оставив изменения
```

- `git restore <файл>` удаляет несохранённые правки безвозвратно.
- `--amend` переписывает последний коммит. Делайте это только до `git push`: если коммит уже на GitHub и им пользуются другие, переписывать его нельзя.
- Забыли добавить файл в коммит: `git add <файл>`, затем `git commit --amend --no-edit`.

## Что не стоит коммитить

- Секреты: пароли, токены, ключи, файлы `.env`. Если секрет всё-таки попал в коммит и ушёл на GitHub, считайте его скомпрометированным: смените его, одного удаления коммита недостаточно.
- Зависимости и результаты сборки (`node_modules/`, `dist/`): их пересобирают из исходников. Добавьте эти папки в `.gitignore`.
- Файл, добавленный в `.gitignore` после того, как Git его уже отслеживает, нужно убрать из индекса: `git rm --cached <файл>`.
