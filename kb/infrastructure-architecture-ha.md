# Отказоустойчивая архитектура

Типовая многоуровневая схема веб-приложения без единой точки отказа и план сегментации сети. Принцип: каждый уровень дублируется, а внутрь частных сетей нет прямого входа из интернета.

## Слои стека

```text
Интернет
   |
[Edge]            Cloudflare DNS + защита от DDoS (прокси включён)
   |
[Балансировка]    HAProxy x2 + Keepalived (общий виртуальный IP)
   |
[Приложения]      Nginx + приложения (Docker / Kubernetes), без состояния
   |
[Данные]          PostgreSQL primary/replica + PgBouncer, Redis, Vault
```

- **Edge:** DNS и защита от DDoS на стороне Cloudflare. Настройте на сервере доступ к 80/443 только с адресов Cloudflare, иначе защиту можно обойти прямым обращением к IP.
- **Балансировка:** два узла HAProxy; Keepalived переносит виртуальный IP при отказе (см. статьи про HAProxy и Keepalived в базе).
- **Приложения:** узлы без состояния, чтобы любой можно было добавить, убрать или перезапустить. Сессии хранятся в Redis, файлы в объектном хранилище.
- **Данные:** репликация PostgreSQL (ведущий и реплика) и пулер соединений PgBouncer, чтобы приложения не исчерпали лимит подключений. Для автоматического переключения ведущего используют Patroni: одной репликации для отказоустойчивости недостаточно.

## Сегментация сети (VPC)

```text
Публичная подсеть        10.0.1.0/24   Bastion, балансировщики, NAT gateway
Подсеть приложений       10.0.2.0/24   Веб-серверы, микросервисы (без публичных IP)
Подсеть баз данных       10.0.3.0/24   БД, Redis, Vault (изолированный доступ)
```

Матрица доступа между подсетями:

- Интернет → публичная: только 80, 443 (и SSH на bastion с ограниченных адресов).
- Публичная → приложений: порты приложений (например, 8080).
- Приложений → баз данных: только 5432, 6379, 8200 и другие нужные порты конкретных сервисов.
- Базы данных → интернет: запрещено. Обновления идут через NAT gateway или зеркало пакетов.
- Администрирование: через bastion (ProxyJump) или VPN, а не прямым SSH к частным узлам.

## Что проверить перед запуском

- Нет ли единой точки отказа: один балансировщик, одна БД, один DNS.
- Проверено ли переключение: остановите HAProxy на ведущем, ведущую БД, один узел приложений и убедитесь, что сервис жив.
- Есть ли резервные копии и пробное восстановление (отдельно от репликации: реплика копирует и ошибочные удаления).
- Мониторинг и оповещения на каждом уровне и логи в одном месте.
- Разрешены только нужные порты по принципу минимальных прав (security groups, файрвол на хостах).
