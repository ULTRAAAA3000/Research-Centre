# Аварийные команды

Эти команды спасают, когда что-то пошло не так, но часть из них необратимо удаляет работу. Перед опасной командой выполните `git status`, а если сомневаетесь, сначала сохраните состояние: `git stash` или отдельная ветка.

## stash: временно спрятать изменения

```bash
git stash                         # спрятать изменения отслеживаемых файлов
git stash -u                      # спрятать и новые (неотслеживаемые) файлы
git stash push -m "описание"      # спрятать с названием
git stash list                    # список спрятанного
git stash pop                     # вернуть последнее спрятанное и удалить из списка
git stash apply                   # вернуть, не удаляя запись
git stash drop                    # удалить последнюю запись
```

- Типичный сценарий: нужно срочно сделать `git pull` или переключить ветку, а текущие правки не готовы. `git stash`, затем `git pull`, затем `git stash pop`.
- Если при `pop` возник конфликт, запись остаётся в списке: разрешите конфликт и удалите её вручную (`git stash drop`).

## reset --hard: полный откат к последнему коммиту

```bash
git reset --hard                  # сбросить ВСЕ несохранённые изменения до HEAD
git reset --hard HEAD~1           # удалить последний коммит и его изменения
git clean -nd                     # показать, какие новые файлы будут удалены
git clean -fd                     # удалить новые (неотслеживаемые) файлы и папки
```

- **Команда необратимо стирает все незакоммиченные изменения отслеживаемых файлов.** Вернуть их нельзя (для закоммиченной работы есть `reflog`, ниже). Если сомневаетесь, сначала выполните `git stash`.
- `reset --hard` не трогает новые файлы, которые Git ещё не отслеживает. Их удаляет `git clean`: сначала запустите с `-n` (показать, но не удалять), потом с `-f`.
- Не делайте `reset --hard` на опубликованных коммитах общей ветки: после `push --force` коллеги получат конфликты.

## revert: безопасная отмена опубликованного коммита

```bash
git revert <commit>               # создать новый коммит, отменяющий указанный
git revert HEAD                   # отменить последний коммит
```

- `revert` не переписывает историю, а добавляет новый коммит с обратными изменениями. Поэтому именно он подходит для отмены того, что уже отправлено на GitHub.

## reflog: найти потерянное

```bash
git reflog                        # журнал всех перемещений HEAD
git switch -c rescue <хеш>        # создать ветку на найденном коммите
git reset --hard <хеш>            # вернуть ветку на найденный коммит
```

- `reflog` хранит ссылки на коммиты, даже если ветка удалена или сделан `reset --hard`. Если вы потеряли закоммиченную работу, найдите её хеш в `reflog` и создайте на нём ветку. Записи хранятся ограниченное время (по умолчанию около 90 дней).
- Работа, которая не была ни закоммичена, ни спрятана в stash, `reflog` не спасёт.
